# Road LOD — согласованные с авторскими правками уровни детализации

Обновлено 5 ноября 2026.

Выполнена подготовка двух уровней по конечной видимой сети. Конечные маршруты получают из штатного рендера `buildOsmTransportNetwork` после применения исходного топологического отбора, затем `scripts/build-authoritative-road-lod.mjs` создаёт gzip `data/osm/road-lod-authoritative-v1.json.gz`. В LOD сохраняются мировые координаты (x,y,z) и идентификаторы дорог, которые действительно представлены в разрешённом наборе. `src/road-lod.js` формирует из них объединённые полосы.

- H > 900 — дальняя обзорная сеть.
- 350 < H <= 900 — средняя детализация.
- При H ≤ 350 — точная детальная дорожная сеть (генерируется в фоне после приближения; сама операция пока тяжёлая).

**Важная защита:** 18 добавленных пользователем дорог и 286 удалённых участков сохраняются благодаря общему `road-editor.js`, который применяет физические вырезы и к готовым LOD, и к детальным мешам после их создания. Изменения исходного OSM и ручных дорог требуют пересборки кеша. Отдельный слепок `data/osm/road-lod-prebuilt-v1.json` на основе сырых OSM не используется на обычном сайте, только при явном `?previewRoadLOD=1`.

**Размеры:** компактный кеш маршрутов около 463 КБ gzip, соответствующие LOD около 93 КБ gzip. Пробная точная сериализация GPU-треугольников заняла 51,5 МБ и отклонена. Музей не загружает этот огромный файл.

**Производительность:** ускорение касается **первого кадра**, на котором больше не выполняется полный расчёт транспорта. Для точных дорог вблизи остаётся отдельная задача по предварительно скомпилированным бинарным чанкам. Сравнение отдельных CI-запусков указывает примерно на 25 секунд против прежних 49–59 секунд полной первоначальной сборки, без гарантии аналогичных результатов на других устройствах.
