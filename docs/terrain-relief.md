# Рельеф Байконура

`data/terrain/baikonur-dem.json` содержит сетку абсолютных высот для территории
музея. Основа — открытые SRTM-derived данные из Mapzen Terrain Tiles. Это
географическая основа крупного рельефа, адаптированная для музейного макета;
мелкие насыпи, современная планировка площадок и геодезическая точность
этими данными не подтверждаются.

## Источник и характер местности

- [AWS Open Data: Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) —
  публичный бакет `elevation-tiles-prod`, доступ без ключа и AWS-аккаунта.
- [Mapzen/Tilezen: sources and coverage](https://github.com/tilezen/joerd/blob/master/docs/data-sources.md) —
  в этой области и на используемом масштабе основой служит SRTM. Номинальное
  исходное разрешение — около 30 м; выбранный zoom 10 имеет пиксель примерно
  106,5 м на широте Байконура. Повышение zoom не повышает точность исходных
  измерений.
- [Terrarium format](https://github.com/tilezen/joerd/blob/master/docs/formats.md) —
  PNG 256 × 256, Web Mercator / EPSG:3857. Высота в метрах:
  `R * 256 + G + B / 256 - 32768`.
- [Attribution](https://github.com/tilezen/joerd/blob/master/docs/attribution.md) —
  **Mapzen. SRTM data courtesy of the U.S. Geological Survey.**
- [NASA Earth Observatory: Baikonur, Kazakhstan](https://science.nasa.gov/earth/earth-observatory/baikonur-kazakhstan-88385/) —
  полупустынная почти плоская равнина, сухие озёра, песчаные участки, дюны и
  следы старого русла Сырдарьи. [ESA](https://www.esa.int/Science_Exploration/Space_Science/Baikonur_Cosmodrome)
  также описывает плоскую степь. Поэтому музей передаёт широкие невысокие
  гряды и понижения, без искусственных гор.

Краткий кредит для интерфейса: **«Рельеф: Mapzen / SRTM — USGS»**, со ссылкой
на реестр источника или эту документацию. Полный кредит выше и в `source.attribution`
должен сохраняться при распространении ассета. Terrain Tiles was accessed on
2026-11-01 from https://registry.opendata.aws/terrain-tiles/.

## Область и формат

Сетка 321 × 321 охватывает world X от **−2600 до 3160**, world Z от
**−2500 до 1980**. Z возрастает с севера на юг. Это включает объединение полных
границ `createMuseumGeography()` и `FLANK_OUTLINE`, с запасом минимум 200
мировых единиц с каждой стороны. Внешний контур космодрома выступает дальше
каталога площадок на восток и север; эти видимые территории также покрыты.
Область остаётся внутри мозаики исходных тайлов.

Координаты берутся непосредственно из `inverseProjectOsm` в
`src/osm-geography.js`, вызываемой генератором через Node.js. Привязка мира:
`worldX = (planX - 650) * 3.4`, `worldZ = (planY - 522.5) * 3.4`.
Географический масштаб: 65 м на единицу плана, или `3.4 / 65` мировой единицы
на реальный метр. Масштаб отдельных музейных экспонатов для DEM не используется.
Точные географические границы, интервалы и исходная проекция записаны в `grid`.

| Поле | Значение |
|---|---|
| `version` | 1 |
| `width`, `height` | 321, 321 |
| `bounds` | `{minX:-2600,maxX:3160,minZ:-2500,maxZ:1980}` |
| `values` | 103 041 целое значение, допустимое для Uint16 |
| `metresPerUnit` | 0,1 м на единицу кодирования |
| `offsetMetres` | 0 м |
| Порядок | `values[row * width + column]`; X растёт внутри строки, Z между строками |
| Декодирование | `heightMetres = offsetMetres + value * metresPerUnit` |
| Шаг сетки | 18 world по X и 14 world по Z; примерно 344 и 268 м |

Точки находятся на границах сетки включительно. При интерполяции последняя
строка и последний столбец должны корректно обрабатываться как крайние значения.
`metresPerUnit` описывает только кодирование высот, а не масштаб горизонтальных
координат. Дециметровое округление не означает дециметровую точность SRTM.

Географические границы: 62,707360–64,131055° E,
45,509581–46,279822° N. Запас относительно объединения каталога и внешнего
контура: 208,126 world с запада, 211,491 с востока, 205,487 с севера и
203,5 с юга. `grid.coverageWorldBounds` и `grid.coverageBufferWorld` описывают
это объединение; границы каталога и контура также сохранены отдельно.
Текущий JSON занимает **445 330 байт**, диапазон закодированных высот —
**67,3–210,2 м**, медиана — 94,1 м. Более высокие отметки появились в
добавленной северо-восточной области: максимум относится к связному
возвышению, не к одиночному пикселю. Основная территория остаётся пологой.

## Обработка высот

1. Загружаются 20 Terrarium PNG: zoom 10, X 690–694, Y 363–366.
   Общий размер PNG — 473 941 байт. URL, размеры и SHA-256 каждого тайла
   сохраняются в JSON.
2. PNG декодируются в абсолютные высоты и собираются в мозаику 1280 × 1024.
   В исходных данных около 62,7635° E / 46,1237° N обнаружены соседние
   значения −236 и 213 м, не соответствующие окружающей равнине.
3. Выполняется один условный фильтр: значение заменяется локальной медианой
   окна 5 × 5, только если абсолютное отличие превышает 12 м. Обычный рельеф
   на этом этапе остаётся прежним. Окна 3 × 3 недостаточно для найденной
   группы ошибочных пикселей. Число замен сохраняется в `source.filter`.
4. После удаления выбросов выполняется **один мягкий проход** разделимого
   фильтра `[0.25, 0.5, 0.25]` по X и Y. Радиус поддержки — один исходный
   пиксель, около 106,5 м. Это уменьшает влияние одиночных ступеней и шума
   перед укрупнением сетки; широкие формы рельефа сохраняются. Вне мозаики
   фильтры используют ближайшее граничное значение; сетка музея до этих
   краёв не доходит.
5. Для узлов музейной сетки применяется билинейная интерполяция из центров
   пикселей Web Mercator; центр первого пикселя — координата 0,5, а не 0.
6. Высоты округляются до ближайшего дециметра (`np.rint`, половины к чётному).
   Ошибка этого кодирования не превышает 0,05 м. `rangeMetres` относится к
   уже закодированным данным. Хеш значений вычисляется по Uint16 little-endian.

В JSON **не запечены** затухание у края, выравнивание дорог и площадок,
вертикальное усиление, уровень водной поверхности или процедурные холмы.
Сохраняется отделение измеренной основы от визуальных поправок сцены.

## Визуальная адаптация в сцене

Текущая адаптация `baikonur-dem-relief-v2`: базовая отметка **68 м**,
вертикальное усиление **2,25**. Исходная прибавка к уровню земли:

```js
const reliefWorld = Math.max(0, heightMetres - 68) * (3.4 / 65) * 2.25;
```

Это осознанное усиление читаемости пологого рельефа на макете; абсолютные
значения в ассете остаются в метрах. Runtime плавно гасит рельеф у внешнего
края и защищает инженерные поверхности: основания зданий, стартовые
комплексы, дороги, железную дорогу, аэродромы и воду. Такие локальные
выравнивания относятся к музейной адаптации, не к измерениям SRTM.
`displayGuidance` фиксирует рекомендуемые параметры, а не изменяет данные.

Для естественного вида на масштабе флангов эта прибавка проходит визуальную
обработку, не меняющую исходный DEM:

- Высота плавно варьируется детерминированным полем на масштабах 280 и 620
  мировых единиц, с максимальной амплитудой 28% от исходной прибавки.
- Ширина перехода от защищённых объектов — 320 мировых единиц, с плавным
  изменением до ±30%. Используется полином пятой степени с нулевыми первой
  и второй производными на концах перехода.
- Два прохода разделимого фильтра `[1, 4, 6, 4, 1] / 16` сглаживают DEM;
  ещё два прохода сглаживают пересечения переходов после выравнивания.
- После фильтрации точные защитные зоны восстанавливаются. Запас равен
  диагонали ячейки плюс 0,05, поэтому даже узкая дорога между вершинами
  остаётся физически плоской.
- Внешнее затухание расширено до 480 единиц с плавной вариацией ±18%.
  Четыре стороны смешиваются произведением коэффициентов, чтобы в углах
  области не возникало диагональной складки.

Цвет флангов наносится одной непрерывной сеткой на рельеф и плоские участки,
включая защитные коридоры. Прозрачность окраски не зависит от прозрачности
края грунта. Прежние плоские заливки отключаются после создания этой сетки;
точные угловатые контуры территорий и отдельная окраска холма Сатурна
сохраняются. Это устраняет ложный уступ на пересечении плоской заливки и
поднятой поверхности.

## Холм Сатурна

Сатурн сохраняет отдельную модель возвышенности и утверждённую высоту
инженерной площадки. Северное и восточное плечи расширены асимметрично:
пологие переходы постепенно соединяют склон со степью, сохраняя различия
в форме и высоте склонов. Контур учитывает подъезд и соседние магистральные
коридоры, где добавка высоты и непрозрачность грунта остаются нулевыми.

Окраска центрального фланга непрерывно проходит через холм и окружающую
поверхность. Сопряжение цветного пятна следует итоговой геометрии; отдельный
плоский слой не пересекает склон. Исходная цифровая модель высот общего
рельефа при этой локальной адаптации не изменяется.

## Воспроизведение

Нужны Python 3.10+, NumPy, Pillow и Node.js. Из корня репозитория:

```sh
python scripts/build-terrain-dem.py --fetched-at 2026-11-01
```

Скрипт скачивает недостающие PNG без авторизации. По умолчанию кеш находится
в системном временном каталоге `baikonur-dem-cache`; в репозиторий пишется
только `data/terrain/baikonur-dem.json`. `--refresh` повторно скачивает тайлы,
`--cache-dir` меняет кеш, `--output` позволяет сохранить проверочную сборку
временным файлом. При обновлении источника указывать фактическую дату доступа.
Зафиксированная дата и те же исходные PNG дают идентичный JSON.

Текущая сборка использует кеш исходных PNG, дополненный восточной колонкой
X 694 для охвата всего внешнего контура:

```sh
python scripts/build-terrain-dem.py \
  --cache-dir /tmp/baikonur-relief-source \
  --fetched-at 2026-11-01
```

Необязательная опция `--clean-mosaic` не обходит обработку: скрипт сначала
воспроизводит фильтр по исходным PNG и требует точного совпадения формы и
значений, затем использует сохранённую мозаику. Для обычной повторной сборки
этот файл не нужен; ранняя мозаика 1024 × 1024 для расширенной области не подходит.
Генератор проверяет покрытие географии и внешнего контура с запасом, принадлежность выборки
исходной мозаике, конечность высот и допустимость Uint16.
Хеши закодированных высот и каждого исходного PNG записаны в ассете.
Повторная сборка расширенной области по PNG проверена: JSON совпадает
побайтно. Фильтр заменил 119 из 1 310 720 исходных значений.
